# FLOW-001 — audit שלמות גרף הלמידה

## היקף ושער בטיחות

הבדיקה בוצעה על בסיס `64a325516f1fa6065a169cb3aa837fb23571da04`, מועמד PR3, בלי למזג אותו ל-`main` ובלי להניח שנפרס לפרודקשן.

ה-audit המקורי הוסיף בדיקות regression בלבד. בהחלטת מוצר מתועדת מ-2026-10-02 אושר להשאיר נושאים קרדיולוגיים מתקדמים, ובהם זיהוי קצב, כחומר העשרה נפרד ממסלול הפעולה הראשי. המימוש הנוכחי מוסיף סיווג והפרדת UI בלבד; לא שונו צמתים, קשתות, תוכן רפואי או משמעות קלינית.

## שיטת הבדיקה

ה-audit מבדיל בין שני סוגי קשתות:

1. **קשתות מוצהרות** — כל `next`, ‏`conditions`, ‏`options` ו-`content.actions` המופיעים ב-JSON. מדד זה משחזר את ספירת ה-audit ההיסטורית.
2. **קשתות ניווט אפקטיביות** — הקשתות שמשתמש יכול לבחור ב-`StepByStepView`, לפי הקדימות בפועל: `content.actions`, אחריהן `conditions`, אחריהן `options`, ולבסוף היעד הראשון של `next`.

Reachability נבדק מהצומת הקנוני `report_departure` לפי קשתות הניווט האפקטיביות. בדיקות נוספות מאמתות יעד חסר, התאמה בין מפתח הצומת ל-`id`, רכיבים מנותקים וסיווג reference מפורש בלבד.
