# Jarvis 66 — runbook להפעלת moderation

סטטוס: `local-plan-only; no-live-actions-authorized`

המסמך מגדיר סדר פעולה עתידי. הוא אינו מעניק הרשאה, אינו כולל ערכים סודיים ואינו
מפעיל migration, admin, automation או purge.

## תנאי פתיחה

1. `main`, ‏CI ו־deployment נקראים חזרה ומצביעים לאותו commit מאושר.
2. שני שערי moderation נשארים `false`.
3. המיגרציות נבדקו על clone/staging מאושר, כולל rollback תפעולי ו־schema readback.
4. קיים גיבוי מאומת ונתיב שחזור; אין להשתמש בתוכן חי בבדיקות.

## bootstrap בעלים יחיד

1. הבעלים מאשר בערוץ פרטי את כתובת חשבון Google המדויקת; אין להכניס אותה למסמך,
   לקומיט, ללוג או להודעת מסירה.
2. מפעיל מורשה מגדיר `ADMIN_EMAIL` כ־Pages secret בפרודקשן, בהזנה אינטראקטיבית בלבד.
   אין להעביר את הערך בשורת פקודה או בקובץ.
3. הבעלים מבצע login חדש. נתיב ה־login הקיים משווה את הכתובת ל־secret וכותב
   `is_admin=1`; אין לבצע `UPDATE users` ידני כברירת מחדל.
4. readback מציג ספירות בלבד: בדיוק שורת admin אחת, זהות Google שאינה guest ו־0
   מנהלים נוספים. אם אחד התנאים נכשל—השערים נשארים כבויים ועוצרים.
5. smoke סינתטי מאמת: guest/user נדחים מפעולות admin; הבעלים קורא queue ומבצע
   פעולה רק על fixture סינתטי מאושר. אין לגעת בתוכן משתמשים חיים.

## גישה מצומצמת לדוח היומי

- מקור: שאילתות aggregate קבועות על `comments`, ‏`comment_reports`,
  `comment_moderation_audit` ו־`community_moderation_maintenance_log` בלבד.
- אין קריאה מ־`users`; אין `content`, מזהי תגובה/משתמש, אימיילים או payload חופשי.
- אין להעניק לאוטומציה token ישיר ל־D1. נתיב עתידי יקבל רק את פלט ה־aggregate
  הקבוע דרך רכיב הפרויקט שכבר מחזיק binding ל־D1.
- היעד יחיד ופרטי לבעלים. כל עוד יעד מאושר וזהות קורא אינם מחוברים, המצב נשאר
  `not_configured` ואין לטעון שמעקב פעיל.
- התדירות היא פעם ביום. יש להשתמש במנגנון המתוזמן היחיד של הפרויקט; אין ליצור
  cron, webhook או polling מקביל.
- הרשאת כתיבה, hide/restore/dismiss, schema, export ו־purge אינן חלק מהרשאת הדוח.

## purge עתידי

1. preview read-only מחזיר ספירה, טווח זמן ומזהים פסאודונימיים בלבד.
2. מאשרים fingerprint מדויק של batch בגודל עד 500.
3. יוצרים גיבוי AES-256-GCM רק לרשומות ה־batch; המפתח מגיע מ־secret חיצוני ואינו
   נכתב לקובץ או ללוג. קובץ הגיבוי בהרשאת `0600` ופג אחרי 7 ימים.
4. purge מותר רק אם ה־backup תקין, לא פג ותואם בדיוק למצב המסד הנוכחי. כל שינוי
   בין preview, backup ו־execute נכשל סגור ודורש התחלה מחדש.
5. נכתב לוג ממוזער עם run ID אטום, fingerprint, digest גיבוי, ספירות וזמנים בלבד;
   הלוג פג אחרי 90 יום.
6. ניקוי גיבויים ולוגים שפגו הוא פעולה נפרדת עם preview ואישור. אין מחיקה שקטה.

## עצירה ו־rollback

- לפני נתוני moderation חיים: ניתן rollback מאושר אחרי גיבוי ובדיקת schema.
- לאחר יצירת נתונים: מכבים תחילה client ואז server ומעדיפים forward-fix; אין DROP
  אוטומטי או rollback מוחק.
- בכל אי־התאמה של admin, schema, fingerprint, backup או ספירות: לא מפעילים ולא
  ממשיכים ל־batch הבא.
