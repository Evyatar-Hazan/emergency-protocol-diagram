## Prehospital Medical Decision Support – Project Specification

---

## 1. מטרת הפרויקט

מטרת הפרויקט היא פיתוח אפליקציית Web מודרנית המציגה **תרשים זרימה קליני אחד, אחיד וברור בעמוד אחד**, המאפשר לחובש בשטח:

* לזהות במהירות את מצב המטופל
* לנווט בצורה לוגית בין פרוטוקולים רפואיים (ABCDE, החייאה, טראומה, חולה)
* להגיע לחשד קליני או אבחנה מבדלת על בסיס שאלות, בדיקות ומדדים
* לקבל הנחיות טיפול ברורות, כולל שימוש בציוד רפואי

המערכת **אינה תחליף לשיקול דעת רפואי**, אלא כלי תומך החלטה המותאם למצבי לחץ וזמן אמת.

---

## 2. עקרונות UX / UI

* הצגת **Flowchart רציף אחד** ללא מעבר בין מסכים
* ניווט מבוסס שאלות כן/לא, בדיקות קליניות ומדדים
* מינימום עומס קוגניטיבי – כל צומת מייצג החלטה אחת בלבד
* היררכיה ויזואלית ברורה בין שאלות, בדיקות ופעולות
* קידוד צבעים סמלי (בשלב עיצוב):

  * 🔴 אדום – סכנת חיים מיידית
  * 🟠 כתום – החמרה אפשרית
  * 🟢 ירוק – מצב יציב
* תמיכה מלאה ב־RTL, עברית כשפת ברירת מחדל

---

## 3. טכנולוגיות

### Frontend

* React + TypeScript
* Vite לבנייה והרצה מהירה
* React Flow או מנוע SVG ייעודי
* TailwindCSS עם תמיכה ב־RTL

### State & Data

* Zustand או Redux Toolkit
* ארכיטקטורה מונעת־דאטא (Declarative)

## 5. מקור נתונים, אתחול וקונפיגורציה

### 5.1 אתחול דאטא – index.html

המערכת חייבת לעלות עם **דאטא ראשוני מובנה**, ללא תלות ב־API חיצוני.

* קובץ `index.html` משמש כ־Bootstrap
* הדאטא מוזרק ל־`window.__INITIAL_FLOW_DATA__`
* הקריאה מתבצעת פעם אחת בזמן אתחול האפליקציה

מטרות:

* Offline-first
* זמינות מיידית
* עבודה מלאה בשטח ללא קליטה

---

### 5.2 JSON ייעודי – מקור אמת יחיד

כל המידע הקליני והלוגי במערכת נשמר **אך ורק בקבצי JSON**:

* פרוטוקולים
* שאלות
* בדיקות
* מדדים
* חוקים וזרימה

עקרונות מחייבים:

* ❌ אין לוגיקה קלינית בקוד UI
* ❌ אין טקסטים או החלטות מקודדות

---

### 5.3 שכבת קונפיגורציה חיצונית (Extensible Config Layer)

המערכת מאפשרת הוספת קבצי קונפיגורציה חיצוניים בעתיד **ללא שינוי במסמך זה**.

#### מטרות

* התאמות ארגוניות או ניסיוניות
* שינוי התנהגות מערכתית
* שמירה על מסמך זה כ־Single Source of Vision

#### מבנה תיקייה

```text
/config
 ├── README.md
 ├── feature-flags.json
 ├── flow-overrides.json
 ├── ui-behavior.json
 └── environment.json
```

#### כללים מחייבים

* יש לבדוק קיום `/config` בעת אתחול
* קונפיגורציה גוברת על ברירת מחדל
* קונפיגורציה משנה התנהגות בלבד – לא מוחקת דאטא

#### סדר טעינה

1. index.html – דאטא ראשוני
2. JSON ברירת מחדל
3. קבצי `/config`
4. Runtime State
